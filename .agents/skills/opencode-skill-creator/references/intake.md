# Capture Intent (Required Gate for New Skills)

For new skills, this step is mandatory. Do not draft SKILL.md, evals, or other files until this interview is complete and the user confirms your summary.

Start by extracting the workflow from the conversation: tools used, sequence, corrections, inputs/outputs, success criteria. Then fill gaps with questions.

## Required Questions

Ask at least 3-5 targeted questions. Cover:

1. What should this skill enable OpenCode to do end-to-end?
2. When should this skill trigger? (phrases, contexts, near-misses)
3. What output format and quality bar?
4. What workflow steps are fixed vs. can be improvised?
5. Should we set up test cases? Skills with objectively verifiable outputs benefit from them; subjective ones often don't. Suggest the appropriate default.

Before moving on, summarize your understanding and ask the user to confirm.

If the user asks to skip intake, warn that final quality will be worse. Proceed only after explicit confirmation.

## Interview and Research

Use a buddy/shadowing stance: mirror the user's real workflow, terminology, handoffs, decision points. Check available MCPs for research in parallel via Task tool. Come prepared to reduce burden on the user.
