# ADR-008: Seguridad del merge de permisos `auto-sub` — guard de colisión dinámico

- **Status**: Resolved (implementado Cycle #2 v3, commit 4519466f `fix(generator): dynamic Object.keys collision detection (H2)`, 7/7 tests verde, regen validate VALID in-sync) · **Fecha**: 2026-08-07 · **Ciclo**: Cycle #1 v3 (Enfoque B2) · **Origen**: H2 (Unit B adversarial, ses_0214c7)
- **Context**: El guard de colisión de `extraPermKeys` en `scripts/lib/generate-opencode-config.js:161-170` valida contra una lista **hardcodeada** `['bash','edit','read','write']` (L163). Los templates `auto-sub` (`permission-templates.json:171-178`) y `readonly` (`:38-47`) incluyen la clave `task`, que NO está en esa lista. Un override `extraPermKeys: { "task": { "*": "allow" } }` atraviesa el guard (L164 no matchea) y `Object.assign` shallow (L169) reemplaza `task: { "*": "deny" }` del template → **escalada de delegación** (un subagente auto/readonly ganaría `task.* = allow`; el fail-closed `task:{"*":"deny"}` de `auto-sub` existe precisamente para impedir delegación). Explotación actual: **latente** — los dos usos vivos de `extraPermKeys.task` (`agent-overrides.json:17-35` sdd-orchestrator, `:48-67` gentleman-vMK-auto) aplican sobre templates SIN clave `task` y usan `"*": "deny"` + allowlist; ningún override vivo escala. El vector queda abierto para cualquier override futuro o comprometido.
- **Decision**: Guard **dinámico**: reemplazar L163 `const templateKeys = ['bash', 'edit', 'read', 'write'];` por `const templateKeys = Object.keys(template);`. Las colisiones se detectan contra las claves REALES del template (hoy: `task` en auto-sub/readonly/orchestrator; mañana: cualquier clave nueva) en lugar de una lista estática. Cambio de 1 línea, fail-closed (colisión → ERROR + exit 1). Acompañante obligatorio: test de regresión en `generate-config.Tests.ps1` para colisión con `task` (el test actual, L87-101, solo colisiona con `bash` — la única clave que el guard ya cubría). Verificado: los 2 overrides vivos del SSoT sobreviven al guard dinámico (adds puros sobre templates sin `task`).
- **Alternatives**: A) Agregar `'task'` a la lista estática — rechazado: sigue siendo mantenimiento manual por clave; cualquier clave futura de template re-abre la vulnerabilidad. B) Deep-merge de `extraPermKeys` dentro del template — rechazado: cambia la semántica (permite sobrescribir parcialmente deny floors) y degrada el fail-closed de `task`. C) Guard dinámico `Object.keys(template)` — **GANADOR**.
- **Consequences**: (+) `task` — y toda clave presente o futura de template — queda protegida del clobber por `extraPermKeys`. (+) SSoT actual intacto (verificado: los overrides vivos son adds puros). (−) Coste: 1 línea + 1 test de regresión. (−) Un override que colisione con una clave de template → ERROR + exit 1 (deseado; hoy sería silencioso). (−) `Object.assign` shallow (L169) permanece como semántica de merge (reemplazo por clave) — el guard ahora la controla por completo.
