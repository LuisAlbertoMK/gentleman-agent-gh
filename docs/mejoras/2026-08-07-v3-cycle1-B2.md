### 2.2 Unit B — Adversarial (ses_0214c7) 🚨 → H2 CRÍTICO
- 4 vectores de evasión H1–H4 sobre el pipeline de permisos. Detalle de H1/H3/H4 en evidencia de Unit B (sesión ses_0214c7).
- **H2 (crítico)** — guard de colisión con blind spot `task`:
  - `scripts/lib/generate-opencode-config.js:163` — `const templateKeys = ['bash', 'edit', 'read', 'write'];` (lista hardcodeada).
  - `permission-templates.json:171-178` (`auto-sub`) y `:38-47` (`readonly`) definen `task: { "*": "deny" }` — clave FUERA de la lista del guard.
  - Vector: `extraPermKeys: { "task": { "*": "allow" } }` → L164 no detecta colisión → L169 `Object.assign(permission, extraPermKeys)` (shallow) REEMPLAZA `task: { "*": "deny" }` por `task: { "*": "allow" }` → **escalada de delegación** (un subagente auto/readonly gana `task.* allow`).
  - Explotación actual: LATENTE (verificado por Unit D): los únicos usos vivos de `extraPermKeys.task` (`agent-overrides.json:17-35` sdd-orchestrator, `:48-67` gentleman-vMK-auto) son adds sobre templates SIN `task` y con deny+allowlist.
  - **Severidad**: HIGH (DoD §1.4: 0 vuln nuevas — FAIL provisional). Unit B lo clasifica crítico; Unit D mantiene HIGH por latencia (sin override malicioso en el SSoT actual).

### 2.3 Unit C — Benchmark (ses_021558, ses_021593) ❌ Gap D
- Medición: §0 baseline regen **263.8 ms** (mediana, contexto orquestador) vs C-retry warm **520.9 ms** (contexto subagente) → regresión **+97.4%** (primera medición: +42.8%).
- **Veredicto**: benchmark no regresivo = **FAIL**.
- **Causa raíz**: NO es Unit A (test-only, no toca código runtime). Es **Gap D de metodología**: el baseline §0 se mide en contexto orquestador y las mediciones del ciclo en contexto subagente (cache warm/cold, estado de máquina, carga) — no comparables.
- **Acción**: documentar el gap (este log) y corregir la metodología en Cycle #2 (medir baseline y ciclo en el MISMO contexto, 5 runs, mediana + IQR, persistir en artefacto machine-readable).
