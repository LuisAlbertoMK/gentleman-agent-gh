## 1. Protocolo v3 — Adaptación al proyecto

Este proyecto (`gentleman-agent-gh`) es un agente/CLI de PowerShell + OpenCode config framework. El protocolo v3 se adapta así:

| v3 Requirement | v3 Adaptación | Source of truth |
|---|---|---|
| Fuente de verdad de gaps | PSSA (static analyzer ≡ ESLint/SonarQube), npm audit (≡ Snyk), git churn + complexity (LOC), tech debt docs (TODOs/ADRs/BITACORA) | `scripts/`, `adr/`, `BITACORA.md`, `git log` |
| Trazabilidad a negocio | Cada gap → justificación de negocio explícita (user priority, score-auto dim, risk, o issue) | CYCLE.md dims, score-auto.ps1, AGENTS.md prioridades |
| Jerarquía de métricas | correctness > security > performance > size/legibilidad | Definida en §2.3 |
| Significancia estadística | 5–10 runs, mediana + IQR para benchmark timings | BenchmarkSeconds (benchmark.ps1 -Snapshot) |
| Entorno aislado | Tests en `$TestDrive` repos (Pester), dry-run en sandbox | Pester `TestDrive:`, `scripts/tests/` |
| Blast radius | Bajo (lint/style/local), Medio (lógica interna/contrato estable), Alto (permiso/security/schema/API contract) | Clasificado por agente |
| Scope lock | Declarar archivos/módulos antes de implementar; desvíos → ADR | Tabla §4 |
| DoD binario | E2E verde + benchmark no regresivo + 0 vulns nuevas + ADR + scope OK | Tabla §5 |
| Rollback | Mapeo commit↔ciclo + separación refactor/fix (Regla Fowler) | Mejora Log por ciclo |

## 3. Jerarquía de métricas (conflicto resolución)

```
correctness > security > performance > size/legibilidad
```

- Un cambio que mejora size a costa de correctness → RECHAZADO
- Un cambio que mejora performance a costa de security → RECHAZADO
- Un cambio que reduce warnings de PSSA (legibilidad) sin afectar tests → ACEPTABLE

## 4. Scope lock (Ciclo 1)

| Módulo | Permiso (read/write/execute) | Justificación |
|---|---|---|
| `scripts/` (no .Tests.ps1) | read/write | Gap atacado (complejidad, PSSA) |
| `scripts/tests/` | read/write | Tests de regresión |
| `adr/` | read/write | ADRs requeridos por DoD |
| `docs/mejoras/` | read/write | Plan + logs |
| `.githooks/pre-commit-gate.ps1` | read | Referencia (solo si scope se extiende) |
| `opencode.json` | read | Regenerado automáticamente, no edit manual |

**Desvío requiere**: ADR mini explicando por qué, aprobado en checkpoint.

## 5. Definition of Done (por ciclo)

- [ ] E2E completo: 0 failures
- [ ] Benchmark no regresivo (mediana/IQR ≥ baseline, jerarquía aplicada)
- [ ] 0 vulnerabilidades nuevas (npm audit)
- [ ] ADR mini escrito (commit↔ciclo↔gap)
- [ ] Scope lock respetado (validate-write-scope.ps1 PASS)
- [ ] Breaker ≥3 ataques (entorno aislado)
- [ ] Regla Fowler: refactor ≠ behavioral en el mismo commit

## 6. Rollback map

Cada ciclo produce commits etiquetados con prefijo de ciclo:
- `C1-fix:`, `C1-refactor:`, `C1-feat:`, `C1-docs:` → revertir ciclo individual: `git revert <commit-range>`
- Mapeo en `docs/mejoras/rollback-map-v3.md` (append-only)

## 7. Presupuesto ciclo

- Máx 4 ciclos en esta sesión
- ≤45 min por ciclo
- Umbral de parada: mejora marginal < 10% vs ciclo anterior
- Checkpoint humano: obligatorio para gaps de blast radius Alto
