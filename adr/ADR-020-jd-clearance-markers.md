# ADR-020: JD review clearance-marker bypass for pre-commit gate

- **Status**: Accepted · **Item**: 3 (2026-08-06, branch `experimento/mejora-autonoma-2026-08-06`) · **Tipo**: process/automation
- **Context**: Quality gate `[9/13] JD review check` in `.githooks/pre-commit-gate.ps1` `Fail`s (BLOCKING) for any staged ROZA-zone file (`scripts/`, `.github/`, …) without a `.jd-cleared` marker, producing recurring noise on every scripts/ commit. The `judgment-day` Skill (L23: "Block push ROZA until JD clearance") mandates blocking — the gate enforces this correctly. The marker system + `FORCE_SHIP` bypass provides an audit trail and a dev-flow escape hatch.
- **Decision**: Add a `.jd-cleared/<path>` marker system + `FORCE_SHIP` env bypass to gate [9/13]. After running `!judgment-day` and obtaining APPROVED, the dev runs `touch .jd-cleared/<path-with-slashes-as-underscores>`. On the next commit the gate finds the marker → `Pass` silently. Without a marker → `Fail` (BLOCKING) with concrete instructions (`!judgment-day` or touch `.jd-cleared/<path>`). `FORCE_SHIP=1` → `Warn` non-blocking (explicit auditable bypass). Markers are gitignored (`.jd-cleared/*`) with a `.gitkeep` exception so the dir ships empty. `tests/` is intentionally outside ROZA zone (covered by check 13 Pester); ROZA zone = `scripts/`, `.github/` (`src/`, `ci/`, `migrations/` do not exist).
- **Alternatives**: A: convert Warn→Fail (block ROZA without JD) — rejected: breaks dev flow (every scripts/ commit needs a marker or FORCE_SHIP). B: commit-msg `#!ship` regex parse — rejected: fragile (message reword loses bypass). C: JSON sidecar state file — rejected: over-engineering vs simple marker files.
- **Consequences**: Recurring ROZA Fail noise eliminated for cleared files; `!ship` bypasses are now explicit & tracked (FORCE_SHIP env). Gate enforces Fail (BLOCKING) for uncleared ROZA files — matches `judgment-day` SKILL mandate ("Block push ROZA until JD clearance"). Verified: Parser syntax OK (0 errors), 3/3 logic cases pass (no-marker→Fail, marker→Pass, FORCE_SHIP→warn-ack).
